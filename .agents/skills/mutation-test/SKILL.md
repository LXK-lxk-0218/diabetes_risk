# mutation-test：列变异体

只读，不改任何文件。

1. 读这一步的规格卡和实现。
2. 按规格卡逐条列 6–10 个“看起来很像对的”错误实现：
   - 每个只违反卡上的一行、只改一处；
   - 写明改哪个文件、哪一行、改成什么、违反卡上哪一条、你预计哪条测试会红。
3. 不要语法错误，也不要一导入就报错的改法：那种改法任何测试都会红，查不出测试的好坏。
4. 优先挑最容易混过去的：边界上的比较符号、分母、默认值、排序、少一层检查、顺序反了。
5. 结果以人实际运行为准：人每次只改一处，跑验收测试，再 `git restore` 改回去。
