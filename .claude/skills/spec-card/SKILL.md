# spec-card：写一张规格卡

只读，不写代码，只产出 `docs/specs/<步骤>.md` 这一个文件（需要时再加一条 `docs/adr/` 下的 ADR）。

1. 先读 `AGENTS.md`、人点名的规格卡和文件。仓库外的材料只认人贴进提示词的那一份，读不到就停下来问，不要自己编。
2. 格式照仓库里最近的一张规格卡：
   - 概要八项：定位、输出、使用者与用法、输入与依赖、分量、边界、成功的样子、未决问题。
   - 需要时加“字段清单”：仓库里读不到的口径。
   - 精确决定七节：接口、不变量、错误与报错文字、位置与依赖方向、证明、升级条件、审查项。
3. 用法示例导入写全、每行用 `print` 输出；注释写期望，不写只有实现以后才知道的值（指纹、`repr`）。
4. 接口表后面写：“表里是对外接口：验收测试和以后的步骤都按这些名字调用；内部怎么拆、叫什么不限，命名照仓库习惯。”
5. 不变量编号列出，每条带“为什么”；“证明”第一条写：验收测试只测公开接口的行为，不 mock 内部函数，不依赖内部数据结构。
6. 名字照仓库已有的习惯起，只定对外要用的名字。拿不准的写进概要第 8 项，给出默认选择，等人定。
7. 不写 notebook 单元号、测试条数、仓库外的工具。写完列出你拿不准的地方，等人审。
